いま世界で起きていること

「検索して、サイトを開いて、買う」が
変わろうとしています

これまでお客様は、自分でGoogleで検索し、お店のサイトを開き、カートに入れて注文していました。 これからは AIアシスタント（ChatGPTなど）に頼むだけで、AIが代わりにお店を見つけ、注文まで済ませる。そんな買い方が始まっています。

💡

これを 「エージェンティックコマース（Agentic Commerce）」 と呼びます。
エージェント＝代理人。AIがお客様の「買い物代理人」になる、という意味です。OpenAI（ChatGPT）やGoogleが本気で進めています。

かみくだいて説明します

お客様 → AI → あなたのお店

お客様はAIに話しかけるだけ。AIがあなたのお店を見つけ、在庫と値段を確認し、注文を確定します。 あなたのお店は、その注文を いつもの受注 として受け取ります。

🧑お客様「白いスニーカー26cm 買っておいて」
→
🤖AIエージェントChatGPT / Gemini がお店探し・比較
→
🏪あなたのお店EC-CUBE が在庫・送料・決済を処理
→
📦注文成立いつも通り出荷するだけ

※ お店側の作業は、ふだんの注文とほとんど変わりません。AI対応の「入り口」をEC-CUBEが用意します。

これまで と これから

お客様との「出会い方」が増える

これまで
  • お客様が自分で検索してサイトに来る
  • 自分でカートに入れて、住所を入力して注文
  • お店のSEO・広告で「見つけてもらう」勝負
  • 接点は「お店のサイト」だけ
これから（が加わる）
  • AIがお客様の代わりにお店を探して比較
  • AIが注文を代行（住所・決済もAI経由）
  • AIに「見つけてもらう」新しい入り口
  • 接点が「AIとの会話の中」にも広がる
🎯

ポイントは 「今のお店をやめる」話ではない こと。今までの販売はそのまま、AI経由という新しい販路が1つ増えるイメージです。

EC-CUBE 4.4 の対応

世界に2つの「AIお買い物ルール」があります

AIとお店がやりとりするには共通のルール（規格）が必要です。いま主流は次の2つ。EC-CUBE 4.4 はどちらにも対応します。

ACPUCP
正式名称Agentic Commerce ProtocolUniversal Commerce Protocol
推進しているのはOpenAI ＋ StripeGoogle（Merchant）ほか
代表的な入り口ChatGPT の即時購入
（Instant Checkout）		Google 経由のAI購入
立ち位置オープン仕様（Apache 2.0）オープン仕様（Apache 2.0）
🤝

難しい名前ですが、店舗オーナーが覚えることは1つだけ：「ChatGPT用（ACP）とGoogle用（UCP）、両方の窓口をEC-CUBEが用意してくれる」。中身の違いは開発チームが吸収します。

しくみ① 商品を知ってもらう

「商品フィード」でAIに商品カタログを届ける

AIがあなたの商品を勧めるには、まず 商品名・価格・在庫 を知ってもらう必要があります。 その「商品カタログの渡し方」が、ACPとUCPで逆向きなのが面白いところ。

ACP＝こちらから届ける（Push）

お店の商品リストを作って、OpenAI側へ送り出す方式。カタログを郵送するイメージ。

🏪お店
→
🤖OpenAI
UCP＝聞かれたら答える（Pull）

お店に「問い合わせ窓口」を用意し、AIが必要なときに聞きに来る方式。最新の在庫をその場で返せる。

🤖AI
→
🏪お店

この「商品フィード／カタログ配信」の土台は、すでに EC-CUBE 4.4 に取り込み済み（マージ済み）です。

しくみ② 購入を完了する

AI経由でも「いつもの購入処理」を通る

ここが一番の安心ポイント。EC-CUBE 4.4 は AI注文専用の特別な仕組みを別に作りません。 通常の購入と同じ「PurchaseFlow」をそのまま再利用します。

🔁 同じ処理を共有するから安心

税の計算・送料・代引き手数料・ポイント付与・在庫の引き当て・注文番号の採番。これらは通常注文とAI注文でまったく同じロジックを通ります。二重管理の心配がありません。

🔑 CheckoutSession という「合言葉」

AIはブラウザのCookieを持ちません。そこで、推測されにくい専用のセッションIDでカートを束ねます。人間の買い物カゴと同じ役割を、AI向けに用意した形です。

✅

店舗オーナーへの意味：在庫・金額・ポイントの計算がAI注文でも「今までと同じ」＝帳簿や在庫がズレない。ここを作り込んだのが 4.4 の肝です。

しくみ③ お金のやりとり

決済は「決済プラグイン」が担当

「AIにクレジットカード情報を渡して大丈夫?」という不安。ここは仕組みで解決されています。

🤖AIお客様の代わりに「支払いトークン」を提示
→
🏪EC-CUBE受け取り窓口だけ用意
→
💳決済プラグイン実際の決済を安全に処理
  • 生のカード番号ではなく 「使い切りの支払いトークン」 をやりとりする設計（Shared Payment Token）
  • 実際の決済処理は 決済プラグイン側（例：サンプル決済／Stripe決済）が担当。本体は窓口だけ
  • 3Dセキュア（本人認証）の中断・再開にも対応する参考実装が用意されている

EC-CUBE 本体は「決済ハンドラの契約（インターフェース）」だけを定義し、実装は決済プラグインが差し込む分業構造です。

もう一つの目玉

MCPサーバー ―
お店のデータをAIに「聞ける」ようにする

エージェンティックコマースが「AIがお客様として買う」話なら、MCPは 「あなた自身がAIに店番を手伝ってもらう」 話です。

💬

Claude や Cursor などのAIツールに、こう聞けるようになります：
「在庫が10個を切っている商品を教えて」「今日の未発送の注文は?」「先月リピートしたお客様は?」
管理画面を何クリックも探さず、会話でお店の状況を把握できます。

MCP（Model Context Protocol）＝ AIツールと外部データを安全につなぐ、いま広く使われている共通規格です。

MCPサーバーの中身

見られる範囲は4分野・すべて「読み取り専用」

📦
商品・在庫
在庫数・価格の確認
🧾
注文
受注状況の把握
👥
顧客・会員
会員情報の参照
🧩
プラグイン
導入状況の確認

🔒 安全のための3つの約束

① 読み取り専用：AIは「見る」だけ。勝手に注文を変更・削除できません。

② 認証つき：管理者がログイン・許可した接続だけ。合言葉（OAuth2トークン）が必要です。

③ 全部記録：AIが何を見たかは監査ログに残ります。

🔌 使うときに必要なもの

EC-CUBE 本体に MCP サーバーが同梱され、/admin/mcp で提供されます。

認証は API プラグイン（4.4対応版）に任せる2層構成。導入すれば URLを入れるだけでAIツールとつながります。

個人情報も見えるため、「どのAIにどこまで見せるか」は管理者が権限で管理します。

デモ ／ イメージ

AIに店番を聞いてみる

MCPサーバーにつなぐと、こんな会話ができます。管理画面を開かなくても、AIがEC-CUBEの中を「読んで」答えてくれます。

 Claude / Cursor — EC-CUBE (MCP)
在庫が10個を切っている商品を、少ない順に教えて
🔧 mcp:product:read
在庫が少ない商品は次の3件です：
・オーガニックコットンTシャツ（白/M）… 残り3
・帆布トートバッグ … 残り6
・ハンドドリップ珈琲 200g … 残り9
今日の未発送の注文は何件?
🔧 mcp:order:read
本日「新規受付」で未発送の注文は 7件 です。うち代引きが2件あります。

※ AIは「見る」だけ（読み取り専用）。在庫を書き換えたり注文を確定したりはしません。実際の見え方は接続するAIツールにより異なります。
